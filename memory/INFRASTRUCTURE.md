# Infrastructure & Delivery Memory

Last curated: 2026-10-08
Primary reader: Infrastructure Specialist, Product Engineer for deploy/runtime concerns.

## Production

Canonical public app: `https://www.unlockvenice.com/trasporti/`.
Private source repository `main` represents production-ready state.

Frontend deploy publishes versioned public payload to Gandi web hosting.

## Runtime-data separation

`runtime-data/` is generated by the transit builder separately from frontend deploy.
Frontend deployment must not delete or synchronize it.

This boundary is non-negotiable because data production has a separate operational lifecycle.

## CI/CD

Normal source flow:
- feature branch;
- PR to main;
- CI/test gate;
- merge/push to main;
- automatic production deploy.

Production deploy uses dedicated Gandi SFTP credentials from GitHub Actions and verifies public version/runtime manifest after upload.

No agent may expose or commit deployment secrets.

## Hosting constraints

Prefer static/client work and managed/serverless capabilities over unnecessary PHP load.
PHP endpoints should remain minimal.
Avoid introducing recurring server jobs without operational need.

## Autonomous development repos

The autonomous Crew works in two public split repos for presentation vs engine/data/tests, then produces PR candidates. Private source/prod remains authoritative.

Failed paid runs must preserve:
- patch;
- file list/stat;
- report;
- draft PR when source changed.

## Staging

T-Sand is used for controlled browser/live acceptance without directly changing production.
