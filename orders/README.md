# Work orders

A work order is the only input the autonomous development workflow accepts.

Each order should contain:
- objective and user-visible outcome;
- current behavior and observed problem;
- non-negotiable constraints;
- relevant architecture/data/privacy constraints;
- acceptance criteria;
- explicit out-of-scope items;
- required staging or manual checks.

Keep one focused change per order. The coordinator decides which specialists are required and in which order they work.
